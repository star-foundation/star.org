# Star.org 创意 IDEA 文档

版本：v1.6（持续更新）
用途：集中记录所有讨论过的产品/增长创意，避免好点子散落在对话历史里找不回来。

---

## 使用说明

- 每条创意一个编号（IDEA-001 递增），编号一旦分配不再更改，即使创意被否决
- **状态**用以下几种：`待评估` `已采纳` `开发中` `已上线` `已否决` `暂缓`
- **优先级**：P0（下一批就做）/ P1（验证后再做）/ P2（长期储备）
- 新增创意时，追加到对应分类表格末尾，不要打乱已有编号顺序
- 被否决的创意不要删除，保留并写明否决理由——避免以后重复讨论同一个已经想清楚为什么不做的点子

### 文案边界（品牌调性，非合规问题）

产品主力场景是**送礼与喜庆纪念**。文案只走明亮、正向的表达：

- 公开文案（落地页、认领页、证书、邮件、社媒）**只写这些场景**：纪念、告白、出生、结婚、周年、毕业、成人礼、人生节点
- **基调统一为温暖、明亮、有归属感**——「认领一颗星，它就成为你的一部分」这种收藏/相伴的感觉
- 站点是给**在世的人**用的，讲的是此刻的欢喜与牵挂——所以公开侧只做明亮主题，**不做主题落地页、不做定向投放、不写进营销物料**
- **这不是合规问题**：合规禁用词表针对的是监管红线（投资/升值/资产/所有权等），属法律风险层面；而场景基调属于**品牌调性取舍**，两者不该混在一张表里——否则合规脚本会误伤合法表达
